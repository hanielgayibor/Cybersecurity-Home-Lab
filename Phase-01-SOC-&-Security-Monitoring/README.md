# Phase 17 — SOC & Security Monitoring

## Objective
Understand how a Security Operations Center (SOC) monitors activity, reviews alerts, and investigates potential security incidents.

## Topics Covered
- Log sources and event records
- Alert triage
- Indicators of compromise
- False positives
- Severity and escalation
- Incident documentation

## Activities
- Identify examples of useful logs from Windows and Linux.
- Practice separating an observation from a conclusion.
- Create a simple alert-triage record with timestamp, affected system, evidence, assessment, and next action.
- If no SIEM is installed, document the workflow conceptually rather than claiming SIEM alerts were generated.

## Analysis and Findings
- Network tools and packet captures can provide useful evidence during investigations, while endpoint logs can add context about system activity.
- A single unusual event is not automatically proof of malicious activity; analysts need corroborating evidence and context.
- Clear notes and consistent escalation steps are important even in a small lab.

## What I Learned
SOC work involves monitoring, prioritizing, validating alerts, documenting evidence, and escalating issues when needed.

## Cybersecurity Relevance
These practices align with entry-level SOC analyst responsibilities, including log review, alert triage, and incident documentation.
