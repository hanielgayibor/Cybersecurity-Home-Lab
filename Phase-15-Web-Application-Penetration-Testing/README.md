# Phase 15 — Web Application Penetration Testing

## Objective
Practice a structured, safe workflow for evaluating a web application in a controlled lab.

## Lab Environment
- OWASP Juice Shop or another intentionally vulnerable local application, if installed
- Web browser
- Developer tools and an authorized testing proxy, if available

## Topics Covered
- Defining scope
- Mapping application functionality
- Reviewing HTTP requests and responses
- Input validation and output handling
- Authentication and access control
- Documenting evidence and remediation

## Activities
1. Confirm the application is running locally or within the authorized lab.
2. Map normal application features and routes.
3. Observe requests and responses using browser tools.
4. Follow the lab's guided exercises and record the expected behavior.
5. Document only issues actually reproduced.

## Analysis and Findings
- The planned environment includes OWASP Juice Shop as a deliberately vulnerable practice application.
- A useful report should include the affected feature, steps to reproduce within scope, observed versus expected behavior, impact, and recommended fix.

## What I Learned
A good web assessment is systematic and evidence-based. Testing should be limited to the agreed scope, and recommendations should explain how to reduce risk.

## Cybersecurity Relevance
These skills support application security testing, vulnerability triage, and communication between security teams and developers.
